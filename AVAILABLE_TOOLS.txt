7. REMEMBER
   ─────────────────────────────────────────────────────────────────────────
   Description: Store a key-value memory for the current session.
                Use this whenever the user mentions something important —
                a topic, a decision, a preference, a project name —
                that should be recalled later in the same conversation.
   Type: Read-Write (Modifies State)
   Endpoint: /tools/remember
   Storage: In-process (session memory, cleared on server restart)
   
   Input Parameters:
     - session_id (string, optional, default: 'default'): Session identifier
     - key (string, required): Short label (e.g., 'current_project', 'user_goal')
     - value (string, required): The value to store for this key
   
   Output:
     - stored (boolean): Confirmation of storage
     - session_id (string): The session ID used
     - key (string): The key stored
   
   Use Case: Persist important information across conversation turns
   Example: remember(key="user_project", value="Media Ingestion Upgrade")

================================================================================

8. RECALL
   ─────────────────────────────────────────────────────────────────────────
   Description: Retrieve a stored memory by key. If no key is given, 
                returns all memories for the session.
                Use this before answering questions that depend on earlier
                context in the conversation.
   Type: Read-only
   Endpoint: /tools/recall
   Storage: In-process (retrieves from session memory)
   
   Input Parameters:
     - session_id (string, optional, default: 'default'): Session identifier
     - key (string, optional): The key to retrieve. Omit for all memories.
   
   Output (Single Key):
     - key (string): The key requested
     - value (string): The stored value
     - found (boolean): Whether the key was found
   
   Output (All Keys):
     - memories (object): Key-value pairs for session
     - count (integer): Number of stored memories
     - session_id (string): The session ID
   
   Use Case: Retrieve previously stored context and preferences
   Example: recall(key="user_project")
            → {key: "user_project", value: "Media Ingestion Upgrade", found: true}

================================================================================

9. FORGET
   ─────────────────────────────────────────────────────────────────────────
   Description: Delete a specific memory key from the session, or clear 
                all memories if no key is given.
   Type: Read-Write (Modifies State)
   Endpoint: /tools/forget
   Storage: In-process (modifies session memory)
   
   Input Parameters:
     - session_id (string, optional, default: 'default'): Session identifier
     - key (string, optional): The key to delete. Omit to clear entire session.
   
   Output (Delete Single Key):
     - cleared (boolean): Whether the key was deleted
     - key (string): The key that was deleted
   
   Output (Clear All):
     - cleared (boolean): Whether the session was cleared
     - session_id (string): The session ID that was cleared
   
   Use Case: Clean up session memory or specific data points
   Example: forget(key="user_project")
            → {cleared: true, key: "user_project"}

10. SEARCH_KNOWLEDGE_DB
    ───────────────────────────────────────────────────────────────────────
    Description: Semantic search over the knowledge base in Supabase (pgvector).
                 Covers ALP docs, transcribed audio, and transcribed video.
                 Same query interface as search_knowledge.
    Type: Read-only
    Endpoint: /tools/search_knowledge_db
    Database: Supabase PostgreSQL with pgvector extension
    Embedding Model: Gemini text-embedding-004
    Table: knowledge_chunks
    
    Input Parameters:
      - query (string, required): The question or topic to search for
      - top_k (integer, optional, default: 3): Number of results to return
      - filter_source (string, optional): Filter by source type
        Possible values: 'audio', 'video', or custom source_type
    
    Output:
      - results (array): List of knowledge chunks
        * id (string): Chunk identifier
        * category (string): Content category
        * question (string): Source or title
        * answer (string): The text content
        * score (number): Similarity score
        * source (object): Source metadata
          - type (string): 'audio', 'video', or 'document'
          - id (string): Source identifier
          - name (string): Source name/label
      - count (integer): Number of results returned
    
    Use Case: Search ingested media transcriptions, video content, audio notes
    Example: search_knowledge_db(query="media ingestion", top_k=5)
    Example: search_knowledge_db(query="video content", filter_source="video", top_k=3)

11. INGEST_MEDIA (UPGRADED - Version 2.0.0 — Multi-Modal Analyzer Pipeline)
    ───────────────────────────────────────────────────────────────────────
    Description: Ingest ANY file into the knowledge base using the Analyzer pipeline
                 (Input -> Classify -> Extract -> Chunk -> Embed -> Store).
                 Routes automatically by file type:
                   • Audio/Video  → Groq Whisper transcription
                   • PDF          → pdfplumber (per-page text extraction)
                   • DOCX         → python-docx (paragraphs + tables)
                   • Image        → Gemini Vision (OCR + description)
                   • .txt / .md   → direct read
                 All content chunked (400 words / 50 overlap), embedded with Gemini,
                 stored in Supabase. Supports local paths OR public URLs.
    
    Type: Read-Write (Modifies State)
    Endpoint: /tools/ingest_media
    Backend Services:
      - Groq Whisper: Audio/video transcription
      - pdfplumber: PDF text extraction
      - python-docx: Word document extraction
      - Gemini Vision (gemini-2.5-flash): Image OCR + description
      - Gemini Embeddings (gemini-embedding-001): Text embedding
      - Supabase: pgvector knowledge storage
    
    Input Parameters:
      - file_path (string, required):
        * Absolute path to local file OR public HTTPS URL
        * Google Drive share links auto-converted to direct download
      - source_name (string, optional): Human-readable label. Defaults to filename.
    
    Output:
      - status (string): 'ok' or 'error'
      - source_type (string): 'audio', 'video', 'pdf', 'docx', 'image', or 'text'
      - chunks_ingested (integer): Number of chunks stored in Supabase
      - source_name (string): Label used
      - transcript_preview (string): First 300 chars of extracted content
      - error (string): Error message if applicable
    
    Supported Formats:
      Audio:     .mp3 .wav .m4a .ogg .flac
      Video:     .mp4 .mov .avi .mkv .webm
      Document:  .pdf .docx .txt .md
      Image:     .jpg .jpeg .png .webp
    
    Analyzer Architecture:
      classify_file() → EXTRACTORS[category]() → chunk → embed → upsert
    
    Use Case: Build a searchable knowledge base from any file type
    Example: ingest_media(file_path="/uploads/report.pdf", source_name="Q1 Report")
    Example: ingest_media(
               file_path="https://drive.google.com/file/d/FILE_ID/view",
               source_name="Product Demo"
             )

USAGE NOTES
================================================================================

Session Memory (remember/recall/forget):
  • In-process storage - cleared when server restarts
  • Default session ID: 'default'
  • Use custom session_id for multi-user scenarios
  • Max stored entries per session: Unlimited (limited by RAM)

Knowledge Base:
  • search_knowledge: Static ALP documentation (19 entries)
  • search_knowledge_db: Dynamic, grows with ingested media
  • Both use semantic similarity scoring (0-1 scale)
  • Embeddings refresh on server startup

Media Ingestion:
  • Timeout: 120 seconds for URL downloads
  • Max file size: Groq API limit (~25MB per file)
  • Chunk size: 500 characters with 50-char overlap
  • Transcription language: Detected automatically by Whisper
  • Storage: Permanent in Supabase (not cleared on restart)

Web Search:
  • Results cached by Serper (time-based)
  • Returns: Title, URL, description (snippet)
  • Disabled if SERPER_API_KEY not configured
